# Source PDF Identity Resolution and Textbook Import Flow\n\nStatus: ADOPTED — 2026-09-22\n\n## 1. Purpose\n\nA raw PDF may be uploaded in two supported modes:\n\n1. Existing-book mode: the administrator selects an existing textbook and uploads its PDF.\n2. Auto-discovery mode: the administrator uploads a PDF without first creating/selecting a textbook.\n\nBoth modes use the same canonical preparation/import pipeline.\n\n## 2. Identity-first rule\n\nPDF → Source identity analysis → Identity reconciliation → Confirmation when declared differs → Resolve/create Textbook → Content Preparation → Workspace P1/P2 → dry-run → canonical import\n\nThe source analysis proposes subject, grade, physical part, printed edition, title, issuer, publication year, printing year, evidence and conflicts.\n\nAI is evidence/proposal only. Node.js/TypeScript remains the authority for canonical identity and persistence.\n\n## 3. Existing-book mode\n\nIf the administrator supplied subject, grade and physical part, those values remain supported.\n\nThe system compares the declared identity with the detected identity.\n\nIf they match, preparation continues.\n\nIf any identity coordinate differs, the operation returns CONFIRM_REQUIRED and performs no preparation/import.\n\nThe confirmation dialog must show the declared and detected values.\n\n### Important identity rule\n\nA mismatch does not edit the existing Textbook row's subject, grade, part or edition.\n\nThose fields participate in the frozen physical identity: Subject + Grade + PhysicalPart + PrintedEdition.\n\nChanging them would actually change the textbook identity. Confirmation therefore means: use the detected identity and continue with that canonical textbook identity, or cancel the import.\n\nIf the detected identity does not already exist, confirmation allows the canonical create path to create it.\n\n## 4. Auto-discovery mode\n\nWhen no complete declared identity is supplied:\n\n1. analyze the PDF;\n2. require sufficient evidence for subject, grade, part and printed edition;\n3. resolve the canonical textbook key;\n4. create the Textbook through ContentAuthoringService when it does not exist;\n5. continue directly into Content Preparation.\n\nCreation is idempotent: an existing canonical identity is reused rather than duplicated.\n\n## 5. Combined P1/P2 source\n\nA combined PDF is source input only.\n\nIf physical-part analysis establishes BOTH, the preparation engine creates independent P1 and P2 packages and the import flow resolves/creates two independent textbook identities.\n\nBOTH and PB are never persisted as textbook identity.\n\n## 6. Uncertain identity\n\nThe system must stop with NEEDS_REVIEW when subject, grade, physical part or printed edition is missing/ambiguous, evidence conflicts, or combined-part boundaries cannot be established.\n\nNo textbook is created in this case.\n\n## 7. Adoption remains separate\n\nTextbook creation/import does not adopt the book to a school.\n\nThe deployment chain remains: Textbook → TextbookAdoption → School + AcademicYear + Term.\n\nPART_1 maps to academic term ordinal 1 and PART_2 maps to academic term ordinal 2. The academic term is never part of textbook identity or Workspace identity.\n\n## 8. Safety and idempotency\n\nThe system must never silently change an existing textbook identity, overwrite a different printed edition, import an unresolved PDF, create PB as a canonical textbook, or infer edition from academic year or filename.\n\nSame identity + same content is unchanged/reusable. Conflicting identity requires explicit confirmation/review.
