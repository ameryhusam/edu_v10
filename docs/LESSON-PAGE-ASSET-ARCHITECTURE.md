# Lesson page and resource asset contract

## Purpose

The content workspace keeps the physical book pages as first-class, immutable-ish assets so lesson authoring, AI refresh, and learner delivery can work from the same evidence without retaining the uploaded source book PDF.

## Canonical workspace

workspace/T01/G04/SCI/ED2026/

```text
ED2026/
├── cover/
│   └── cover.png
├── unit_01_<slug>/

│           ├── audio/
│           └── video/

```

pages/page_NNN.* is the authoritative visual representation of the printed lesson page. The filename uses the printed page number, not the physical PDF index.

ai_pages/page_NNN.* is the matching pedagogical explanation/summary for the same printed page. It is optional: it may be generated by an AI workflow or added/edited by an authorised user. The pair is keyed by printed page number.

The resource/ tree is an editable physical-resource shelf. It may contain images or files belonging to flashcards, questions, concepts, misconceptions, audio, and video. These files are discovered during workspace reconciliation and registered as ContentAsset records; they are not written directly to Prisma by Python.

## Cover

The first physical PDF page is rendered to cover/cover.png when rendering is available. It is registered as a PAGE_IMAGE asset with scope TEXTBOOK and a cover/ relative path. The textbook administration read model exposes a streaming URL so the Materials tab can display the cover without exposing storage internals.

## AI request lifecycle

1. Select the lesson and optional page range.
2. Read the canonical files from pages/.
3. Copy the selected images to a temporary request directory.
4. Send that temporary bundle to the AI provider.
5. AI returns draft concepts/questions/flashcards/misconceptions/explanations with printed-page evidence.
6. Validate evidence against deterministic grounding.
7. Save only draft analysis under the lesson analysis area.
8. Human approval is required before canonical import.
9. Temporary AI request files are deleted.

The canonical pages/ files are never replaced by AI analysis.

## Learner page viewer

The staff/learning UI can request: GET /api/v1/content/lessons/:lessonKey/assets

The response contains the physical lesson pages, matching IMAGE_SUMMARY assets, and other lesson media. The page viewer pairs original and AI page assets by pageStart and lets the user switch between the book page and AI explanation.

The image bytes are streamed through the existing asset route with checksum, range, and cache metadata.

## Import mapping

Python remains responsible for PDF reading, page mapping, rendering, slicing, and deterministic grounding.

Node remains responsible for: workspace -> validation -> ContentImportService -> ContentAssetService -> DB

ContentAsset stores physical binary identity and provenance. LearningResource stores the pedagogical meaning of a resource. A page image is therefore not forced into LearningResource.
