
# التقرير الشامل لتدقيق البنية التحتية، دورة الحياة، وفجوات البيانات في نظام Edu7
### (Autonomous Architecture, Lifecycle & Data Flow Gap Audit)

## 1. التقييم المعماري العام وهُوية النظام (Executive Architectural Verdict)

يُمثل مشروع **Edu7** حالة معمارية فريدة تجمع بين **نواة خلفية (Backend) بالغة النضج والانضباط الرياضي والتربوي** مبنية وفق معمارية المنافذ والمحولات (Ports & Adapters / Hexagonal Architecture) ونمذجة المجالات المقيدة (Bounded Contexts)، وبين **واجهة أمامية (Frontend) مجزأة وغير مكتملة المسارات**، تحولت في كثير من أجزائها إلى مجرد لوحات عرض قراءة فقط (Read-Only Dashboards) أو شاشات حجز مؤقت (Placeholders) تقطع تدفق رحلة التعلم.

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                             Edu7 ARCHITECTURAL REALITY                           │
├──────────────────────────────────────────────────────────────────────────────────┤
│ BACKEND CORE:                                                                    │
│  - Bounded Contexts صريحة، حقن تبعيات صارم عبر Composition Root (container.ts)  │
│  - خوارزميات تعلم تكيّفي حقيقية (IRT 2PL/3PL CAT, BKT Replay, Ebbinghaus Decay)  │
│  - عدم السماح بكتابة التمكن يدوياً (Mastery is a pure function of evidence)    │
│  - سجل أحداث وتتبع فجوات (Remediation Episodes & Decision Logs)                  │
├──────────────────────────────────────────────────────────────────────────────────┤
│ FRONTEND EXPERIENCE:                                                             │
│  - مسار الطالب: مكتمل بنسبة 65% ولكنه ينتهي بحلقة مفرغة عند اتخاذ القرار التكيفي│
│  - مسار المعلم: مجرد قائمة أسماء (Roster) وأرقام مجمعة؛ 70% من التبويبات وهمية    │
│  - مسار ولي الأمر: مراقبة سلبية معزولة، لا توجد مهام حقيقية أو تفاعل              │
│  - مسار المؤلف (Author): مجرد قراءة للشجرة، واجهات التأليف الفعلية غير متصلة     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 2. إعادة بناء دورة الحياة الكاملة (Canonical Lifecycle Reconstruction)

لقد قمنا بتشريح طبقات النظام الـ 23 لكل قدرة (Capability) وظيفية لاكتشاف أين تكتمل الدورة وأين تنكسر:

```
[DATABASE] ➔ [DOMAIN MODEL] ➔ [DOMAIN RULES] ➔ [ENGINE] ➔ [SERVICE] ➔ [API ROUTE] ➔ [SERVER STATE]
   ➔ [UI] ➔ [USER ACTION] ➔ [VALIDATION] ➔ [STATE CHANGE] ➔ [PERSISTED RESULT] ➔ [EVIDENCE]
   ➔ [ANALYTICS] ➔ [MASTERY UPDATE] ➔ [RECOMMENDATION] ➔ [BACK TO LEARNING]
```

### أ. دورة التقييم والتعلم التكيفي (Adaptive Assessment Cycle)
* **المسار الفعلي:**
  1. الطالب يفتح الدرس `GET /learning/lesson` ➔ يقرأ المحتوى `READING`.
  2. يضغط على اجتياز الدرس ➔ يبدأ محاولة `POST /assessment/attempts` بنوع `LESSON_CHECK`.
  3. يجلب السؤال التالي التكيفي `GET /assessment/attempts/:key/next-item` ➔ يتم حساب القدرة عبر **IRT EAP** واختيار السؤال المناسب حسب الصعوبة والتمييز.
  4. يجيب الطالب ➔ `POST /assessment/answers` ➔ تقييم الإجابة `evaluateAnswer` ➔ رصد المفهوم الخاطئ `diagnoseMisconception` ➔ توليد شواهد التمكن `buildEvidence` ➔ حفظ الشاهد في `MasteryEvidence`.
  5. انطلاق زناد التمكن `recomputeTrigger` ➔ إعادة تشغيل نموذج **BKT Replay** بالكامل وحساب التلاشي الزمني **Ebbinghaus Decay** ➔ تحديث `ConceptMastery`.
  6. انطلاق زناد المعالجة `remediation.refresh` ➔ فتح أو تحديث حلقة معالجة `RemediationEpisode`.
  7. منح نقاط الخبرة `rewardTrigger` ➔ قيد جديد في `XpLedgerEntry`.
* **موقع الانقطاع:**
  - عند انتهاء الاختبار يظهر ملخص الدرجات، ولكن **زر العودة لا يوجّه الطالب إلى الفجوة المشخصة** ولا يعرض له المصادر العلاجية المقترحة؛ يتم فقط إعادة تحميل الدرس والمسار.

### ب. دورة التوصية والنشاط القادم (Next-Step Recommendation Cycle)
* **المسار الفعلي:**
  1. شاشة لوحة تحكم الطالب `StudentDashboardPage` تستدعي `GET /learning/next-step`.
  2. الباكيند يشغّل محرك `decideNextActivity` بدقة بالغة (1- معالجة خطأ مفاهيمي، 2- مراجعة تباعدية لمفهوم متلاشٍ، 3- فك حجب متطلب سابق عبر شجرة الاعتمادية، 4- تعلم، 5- تدريب، 6- تقييم).
  3. بطاقة الواجهة `NextStepCard` تعرض التوصية بدقة (الأيقونة، النص المفسر للقرار التربوي، المفهوم المستهدف).
* **موقع الانقطاع الفادح:**
  - زر البطاقة `onStart` مبرمج كالتالي:
    ```tsx
    onStart={() => navigate(`/path${selected ? `?textbook=${selected}` : ''}`)}
    ```
  - **أياً كان القرار التربوي الصادر من المحرك** (`REMEDIATE`, `REVIEW`, `UNBLOCK`, `PRACTISE`)، يتم تحويل الطالب إلى فهرس الكتاب العام `/path`! لا يتم فتح بطاقات المراجعة، ولا جلسة التدريب، ولا الدرس المعالج. المحرك اتخذ قراراً عبقرياً والواجهة ألقت به في الفراغ!

### ج. دورة التكليفات والواجبات (Instructional Plans & Obligations Cycle)
* **المسار الفعلي في الباكيند:**
  - المعلم ينشئ خطة `POST /instruction/plans` (درس، مفهوم، مراجعة، خطة علاجية).
  - الخطة تنتقل من `DRAFT` إلى `PUBLISHED` عبر `POST /instruction/plans/:key/publish`.
  - النظام يولد التزامات للطلاب `LearnerObligation` تلقائياً عبر فحص الحضور والتسجيل.
  - الطالب يقرأ واجباته المستحقة عبر `GET /instruction/due-work`.
  - ولي الأمر يتابع مهام أبنائه عبر `GET /instruction/parent/tasks`.
* **موقع الانقطاع:**
  - **انقطاع 100% في الواجهة الأمامية!**
  - لا توجد شاشة لإنشاء الواجبات للمعلم (`/teacher/assignments` تحول لـ Placeholder).
  - لا توجد شاشة لعرض الواجبات المطلوبة في لوحة الطالب.
  - لا توجد شاشة لمتابعة الواجبات لولي الأمر (`/parent/work` تحول لـ Placeholder).
  - نموذج كامل في قاعدة البيانات والخدمات والـ APIs ميت تماماً من منظور تجربة المستخدم.

## 5. تدقيق بنية المجال والتقسيم المعماري (Domain & Clean Architecture Audit)

### نقاط القوة الاستثنائية:
1. **انضباط الـ Hexagonal Architecture:** لا يوجد تسريب لـ Prisma أو SQL داخل مجلدات `domain` أو `application`. طبقة المجالات نقية 100% وتعتمد على واجهات `ports.ts`.
2. **مركزية الربط (Composition Root):** ملف `src/composition/container.ts` هو المكان الوحيد الذي يتم فيه حقن التبعيات وربط المنافذ بالمحولات، وهو ما يمنع الوصول الخفي بين السياقات.
3. **مبدأ الأمان التنازلي في الوصول لبيانات الطالب:** استخدام بروتوكول صارم في `learner-access.ts` يميز بين ما هو قابل للتفويض (كقراءة ولي الأمر أو المعلم لتاريخ الطالب) وما هو غير قابل للتفويض إطلاقاً (كبدء اختبار أو حل سؤال أو سؤال المساعد الذكي التي تتطلب حصراً `requireSelfLearner`).

### الانحرافات والفجوات البنيوية (Architectural Flaws):
1. **غياب كائن الفصل الدراسي الصريح (The Missing Section/Class Aggregate):**
   - اتخذ النظام قراراً بأن *"الفصل عبارة عن استعلام فوق التسجيلات" (Class is a query over enrollments)*.
   - **النتيجة الكارثية:** المعلم لا يملك كياناً اسمه "فصلي" أو "طلابي". كل معلم في المدرسة يرى جميع طلاب الصف الدراسي لنفس المرحلة. لا يمكن تخصيص واجبات لشعبة معينة (أ / ب) ولا يمكن تعيين مدرس لمادة محددة داخل فصل محدد.
2. **تسريب منطق القوائم والتجميع في مكونات الواجهة الأمامية:**
   - رغم نظافة الباكيند، فإن الواجهة الأمامية في شاشة مثل `LearningPathPage` و `ContentOutlineBrowser` تضطر لعمل عمليات تسطيح وتجميع يدوي (`flatLessons`, `grouping`) كان يجب أن تعود من الـ Read Model جاهزة للاستهلاك المباشر.
3. **ازدواجية الـ APIs لنفس الغرض الإداري:**
   - وجود `src/interface/http/administration.routes.ts` بالتوازي مع `textbook-administration.service.ts` و `content.routes.ts` يخلق ارتباكاً في أي مسار يملك تحديث الكتب الدراسية ونشرها وتعيينها للمدارس (`adoptions`).

## 6. تدقيق واجهات برمجة التطبيقات (API Audit: Action vs CRUD)

الباكيند يتبع في معظمه فلسفة **Action APIs** الممتازة بدلاً من CRUD الساذج، ولكن هناك فجوات في التكامل:

```
┌────────────────────────────────────────┬─────────┬──────────────────────┬─────────────────────────────────────────────────────────┐
│ الـ Endpoint                           │ النوع   │ المستهلك في الواجهة │ المشكلة / التقييم                                       │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ POST /api/v1/assessment/answers        │ Action  │ ExamRunner           │ ممتاز. يسجل إجابة، يصحح، يحدث التمكن، يمنح النقاط.     │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ GET /api/v1/learning/next-step         │ Action  │ StudentDashboard     │ ممتاز في الباكيند، لكن مخرجه معطل وظيفياً في الـ UI.     │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ POST /api/v1/instruction/plans         │ Action  │ معدوم (Orphan)       │ لا يوجد استدعاء له في الواجهة الأمامية إطلاقاً.         │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ GET /api/v1/remediation/tracker        │ Action  │ معدوم (Orphan)       │ مخصص لمتابعة تعثر الطلاب، لم يُربط بأي شاشة معلم.       │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ POST /api/v1/tutoring/ask              │ Action  │ معدوم (Orphan)       │ خدمة المعلم الذكي جاهزة ومحرومة من واجهة مستخدم.        │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ GET /api/v1/analytics/cohort           │ Action  │ TeacherHome          │ يعيد توزيع الطلاب ومستوياتهم، لكنه غير قابل للتفريع.    │
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ GET /api/v1/analytics/learner          │ Action  │ معدوم (Orphan)       │ واجهة تفصيلية لتمكن الطالب لا يستدعيها المعلم أو الوالد.│
├────────────────────────────────────────┼─────────┼──────────────────────┼─────────────────────────────────────────────────────────┤
│ POST /api/v1/content/textbooks         │ CRUD    │ RecordEditor (Admin) │ إنشاء كتاب مدرسي؛ معزول عن عملية التأليف المنهجي.       │
└────────────────────────────────────────┴─────────┴──────────────────────┴─────────────────────────────────────────────────────────┘
```

## 7. مقارنة دورة الحياة مع الأنظمة التعليمية الحديثة (Lifecycle Difference Register)

| القدرة التعليمية (Capability) | دورة الحياة الفعلية في Edu7 | دورة الحياة المعيارية للأنظمة الحديثة (LMS/ITS) | نوع الاختلاف (Difference Type) | مستوى الخطورة والتقييم |
|---|---|---|---|---|
| **التشخيص وتحديد المستوى الأولي (Diagnostic Placement)** | لا توجد دورة تشخيص أولية؛ الطالب يبدأ فوراً من الدرس الأول للكتاب المدرسي | اختبار أولي تكيفي يحدد تموضع الطالب ونقاط انطلاقه ويسقط المفاهيم المتقنة سلفاً | **MISSING CAPABILITY** | **HIGH**: إجبار الطالب على دراسة ما يتقنه يسبب الملل ويهدر وقت التعلم التكيفي. |
| **تقييم التمكن وإعادة الحساب (Mastery Evaluation)** | إعادة تشغيل BKT Replay وتطبيق النسيان التباعدي فور كل إجابة بدقة بالغة | مطابقة تامة لأحدث معايير Intelligent Tutoring Systems مع تفوق رياضي لـ Edu7 | **GOOD DIFFERENCE** | **EXEMPLARY**: بنية متفوقة تمنع التلاعب اليدوي بدرجات التمكن. |
| **التدخل العلاجي التلقائي (Automated Remediation)** | المحرك يكتشف المفهوم الخاطئ ويفتح حلقة علاجية في الخلفية دون أن يراها الطالب | فتح مسار بديل للتعلم (Flipped Micro-learning) بأسلوب شرح مختلف واختبار موازٍ | **ARCHITECTURAL ERROR** | **CRITICAL**: النظام يرصد المرض ولا يقدم الدواء للطالب على الشاشة. |
| **حلقة إسناد وتقييم الواجبات (Assignment Loop)** | نموذج خلفي مكتمل بدون شاشات للمعلم لتعيين الواجب أو متابعة نسبة الإنجاز | المعلم يحدد المهمة ➔ تظهر في جدول الطالب اليومي ➔ إشعار بالموعد ➔ تصحيح ومتابعة | **DESIGN PROBLEM** | **BLOCKER**: النظام عاجز عن استبدال الـ LMS التقليدي في المدارس. |
| **الربط بين المعلم والفصل (Roster Scoping)** | استعلام فضفاض يشمل كل طلاب الصف لنفس المدرسة بغض النظر عن تخصص المعلم | تعيين المدرس للشعبة والمادة (e.g. أ. أحمد -> سادس/ب - رياضيات) | **ARCHITECTURAL ERROR** | **CRITICAL**: لا يمكن لأي مدرسة استخدام النظام بصلاحيات تدريس واقعية. |
| **مشاركة ولي الأمر (Parent Engagement)** | شاشة مراقبة لقراءة نسب التقدم لدروس الكتب، مع حظر كامل لأي تفاعل أو إسناد | إشعار ولي الأمر بالفجوات الحرجة، مهام منزلية مساندة، تقارير تقدم دورية | **ACCEPTABLE DIFFERENCE** | **NEUTRAL**: الحظر الأكاديمي سليم تربوياً، لكن غياب التوجيه يجعله شاشة ميتة. |

## 8. مستخرجات الآثار من النظام القديم (Legacy Archaeology)

أثناء فحص مجلد `legacy/`، تم اكتشاف **كنوز برمجية ومنطقية صحيحة** فُقدت تماماً أثناء عملية الترحيل (Migration) ولم تنتقل إلى النسخة الجديدة:

1. **معالجة واستيراد الكتب المدرسية والملفات (PDF Slicing & TOC Extraction):**
   - في `legacy/src/services/curriculum/pdf-slicing.service.ts` و `toc-extraction.service.ts`: كان يوجد منطق حقيقي لتقطيع كتب الـ PDF واستخراج فهرس الدروس والمفاهيم آلياً وبناء الوحدات.
   - **الوضع الحالي:** تم استبداله بنموذج إدخال بيانات يدوي يرهق مدخلي البيانات، مما يجعل إدخال المناهج اليمنية بطيئاً ومعقداً.
2. **استيراد ملفات إكسل للمناهج والأسئلة (Textbook Excel Importer):**
   - في `legacy/src/services/curriculum/textbook-excel-import.service.ts` و `unified-workbook.builder.ts`: وجد نظام ناضج لمعالجة قوالب إكسل الموحدة، مع معالجة التعارضات (`textbook-import.conflict.ts`).
   - **الوضع الحالي:** يحتوي الباكيند الجديد على `content-import.service.ts` ولكنه يقبل هياكل JSON مجردة لا يستطيع أي مؤلف مناهج غير تقني التعامل معها، وتغيب الواجهة بالكامل.
3. **فحص صحة شبكة المناهج والمتطلبات السابقة (Curriculum Network Health):**
   - في `legacy/src/services/textbook/curriculum-health.service.ts` و `concept-prerequisite-network.service.ts`: كان هناك نظام تدقيق يكتشف: المفاهيم المعلقة التي ليس لها متطلبات، المفاهيم التي ليس لها أسئلة تقيسها، والدروس الفارغة من المواد.
   - **الوضع الحالي:** غائب تماماً؛ يمكن لمؤلف المحتوى حالياً نشر كتاب مدرسي يحتوي مفاهيم معزولة بلا أسئلة، مما يؤدي لانهيار محرك `RunAdaptiveExam` لاحقاً عند الطالب بعطل `empty_item_pool`.
4. **تكامل التخزين السحابي لمواد المعلمين (Drive Importer):**
   - في `legacy/src/services/materials/google-drive-sync.service.ts`: كان المعلم يستطيع ربط مواده وملخصاته المرفوعة على Google Drive بالدروس.
   - **الوضع الحالي:** الرابط في النظام الجديد مجرد حقل نصي `url` يدوي في قاعدة البيانات.

## 10. حزمة الميزات الجديدة المنضبطة (Disciplined New Features Portfolio)

تطبيقاً لمعايير الابتكار المنضبط المشترطة (A, B, C, D, E):

### ميزة 1: "الانطلاق الذكي المباشر للنشاط القادم" (Contextual Next-Step Launcher)
* **المعيار المحقق:** B (Required by existing business flow) + D (Adaptive learning opportunity).
* **القيمة التربوية:** تحويل قرار المحرك التكيفي من مجرد توجيه نصي إلى بيئة تفاعلية فورية.
* **البنية التحتية المتوفرة:** محرك `decideNextActivity` مكتمل و `GetNextStepUseCase` يعمل بنجاح.
* **ما ينقص لتكتمل:**
  - تعديل زر `onStart` في `StudentDashboardPage` ليفحص `step.activity`:
    - إذا كان `REVIEW` ➔ يفتح نافذة منبثقة لبطاقات المفهوم `TreasureDeck` فوراً.
    - إذا كان `PRACTISE` أو `ASSESS` ➔ يطلق `ExamRunner` بمفهوم النشاط المحدد دون وساطة.
    - إذا كان `LEARN` ➔ يوجه إلى شاشة الدرس المحدد `navigate(/lesson?lesson=...&concept=...)`.
    - إذا كان `REMEDIATE` ➔ يفتح المورد العلاجي المشخص مع تمرين تثبيت فوري.

### ميزة 2: "شعبة الفصل وتعيين المعلم" (Teacher Section Assignment Aggregate)
* **المعيار المحقق:** A (Required by existing DB data) + C (Educationally necessary).
* **القيمة التربوية:** تمكين المعلم من إدارة طلابه الحقيقيين الذين يُدرسهم بالفعل، وتقسيم الصفوف المزدحمة إلى شعب واقعية (أ، ب، ج).
* **البنية التحتية المتوفرة:** جدول `School`, `Grade`, `Subject`, `Enrollment` في Prisma.
* **ما ينقص لتكتمل:**
  - نموذج بسيط في Prisma: `ClassSection` (SchoolId, GradeId, Name: "الشعبة أ")، و `TeacherAssignment` (TeacherId, SectionId, SubjectId).
  - تحديث `rosterReader` ليعتمد على `TeacherAssignment` عندما يكون المستعلم معلماً.
  - واجهة في صفحة المدرسة للإدارة لتوزيع الطلاب على الشعب وتعيين المدرسين.

### ميزة 3: "لوحة رادار التدخلات العلاجية للمعلم" (Teacher Remediation Radar)
* **المعيار المحقق:** A (Existing DB support: `RemediationEpisode`) + E (Monitoring opportunity).
* **القيمة التربوية:** إشعار المعلم فوراً بالطلاب الذين يكررون نفس المفهوم الخاطئ، لعمل حلقة تدريس جماعية أو فردية موجهة.
* **البنية التحتية المتوفرة:** مسار `GET /api/v1/remediation/tracker` شغال 100% في الباكيند ويعيد قائمة المتعثرين ونوع الفجوة.
* **ما ينقص لتكتمل:**
  - بناء شاشة `web/src/pages/teacher/interventions.tsx` واستدعاء `remediation.tracker`.
  - زر بضغطة واحدة يتيح للمعلم إنشاء خطة علاجية تلقائية `POST /instruction/plans` للطلاب ذوي الفجوة الواحدة.

### ميزة 4: "المساعد التعليمي المنهجي المباشر" (In-Lesson AI Tutor Drawer)
* **المعيار المحقق:** A (Existing DB support: `AiInteraction`, `AiQuota`) + D (Adaptive learning opportunity).
* **القيمة التربوية:** دعم الطالب في لحظة تعثره داخل نص الدرس وشرح المصطلحات الصعبة باللغة العربية المناسبة للمرحلة العمرية دون الخروج من المنهاج.
* **البنية التحتية المتوفرة:** `POST /api/v1/tutoring/ask`، ونموذج `GeminiProvider`، وفلاتر حماية المحتوى والكوتا.
* **ما ينقص لتكتمل:**
  - إضافة زر عائم (Floating Tutor Button) داخل `LessonPage`.
  - نافذة جانبية منبثقة (Drawer) ترسل السؤال وسياق الدرس للـ API وتستقبل الشرح.

> **خلاصة التدقيق:**
> مشروع **Edu7** يحمل في جوهره البرمجي (Backend Domain Core) بنية فائقة الجودة من أندر ما يُصمم للأنظمة التعليمية العربية، بخوارزميات رياضية وتربوية رصينة ومحمية. المشكلة المركزية تكمن في أن **واجهات المستخدم (Frontend) شُيدت بشكل منفصل دون أن تُكمل دورات حياة تلك الخوارزميات**. تطبيق التوصيات وسد الفجوات المسجلة أعلاه سيحول Edu7 فوراً إلى منصة تعلم ذكية وتكيفية رائدة على أعلى المعايير العالمية.
