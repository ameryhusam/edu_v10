## 1. البنود المفتوحة مرتَّبة بالخطورة — Open items by severity

### 🔴 عالٍ — يُخلّ بصحّة النظام

#### C1. تكافؤ التصدير — ✅ **مغلق** (2026-09-13)

**الحقيقة المقيسة:** الاستيراد يقبل `misconceptions[]` و`learningResources[]`
كمجموعات من الدرجة الأولى، والتصدير **لا يعيدهما إطلاقًا**.

```
GET /content/textbooks/EDU-MATH-G07-T1-EDNAT2026/export
→ top-level keys: [concepts, lessons, meta, prerequisites, questions, textbook, units]
   misconceptions: (absent)   learningResources: (absent)
```

قاعدة البيانات تحوي **57 تصوّرًا خاطئًا و114 موردًا** — البيانات موجودة، والمصدِّر
لا يقرؤها. `readExportable` في `content.repository.ts:703` يصل إلى التصوّرات
**فقط** عبر `choices.misconception.select.key`.

**لماذا هذا 🔴 وليس تجميليًّا:** التصدير هو مسار النسخ الاحتياطي والترحيل. اليوم
`import(export(X)) ≠ X` بصمت — يُفقد 57 تصوّرًا و114 موردًا **دون أي خطأ**.
الفقد الصامت أسوأ من الفشل الصريح.

**الإغلاق:**
1. إضافة قراءة المجموعتين في `readExportable` (مستوى أعلى، لا داخل المفهوم).
2. **اختبار ذهاب-وعودة حقيقي**: صدِّر → استورد إلى كتاب جديد → صدِّر ثانيةً →
   قارن بايت ببايت. هذا الاختبار وحده يمنع تكرار العيب، لأنّه يفشل على أيّ
   مجموعة تُنسى مستقبلًا.
3. تأكيد التماثل: إعادة الاستيراد تعطي `unchanged` للكل.

##### ما تبيّن فعليًّا عند الإغلاق — What the round trip actually found

العيب كان **أوسع من مجموعتين منسيتين**. تشغيل ذهاب-وعودة حقيقي على كتاب
الرياضيات كشف أربعة مواضع فقد، ثلاثة منها لم تكن في التشخيص الأصلي:

| الفقد | الطبقة | الحالة |
|---|---|---|
| `misconceptions` و`learningResources` غائبتان من التصدير | التصدير | ✅ |
| `slug` غير مُخزَّن أصلًا للتصوّرات والموارد | **المخطَّط** | ✅ |
| `orderIndex` للمورد غير مُخزَّن | **المخطَّط** | ✅ |
| `startPage`/`endPage`/`estimatedMins`/`pageNumber` و`difficulty`/`importance`/`masteryThreshold`/`isCore` تُهمَل عند الاستيراد | **الاستيراد** | ✅ |
| `orderIndex` للخيارات: الحزمة 1-based والنظام 0-based | المحوِّل | ✅ |

**السبب الجذري للـ`slug`:** المفتاح يُشتقّ بتجزئة أحادية الاتجاه
(`<conceptKey>-MIS<fp8>` عبر FNV-1a)، فلا يمكن استرجاع الـ`slug` منه. بدون
عمود مُخزَّن كان التصدير **عاجزًا بنيويًّا** عن ذكر أيّ تصوّر يصف — لا مجرد
«نسي أن يقرأ». أُضيف عمودان `slug` مع `@@unique([conceptId, slug])`.

**النتيجة المقيسة — الكتابان معًا:**

```
collection        orig  exported  identical
units                7        7   True
lessons             27       27   True
concepts            55       55   True
prerequisites       54       54   True
misconceptions      55       55   True
learningResources   55       55   True
questions          110      110   True
```

والعلوم كذلك `True`. المقارنة تتجاهل `key` و`status` فقط، وهما في
`NON_IMPORTABLE_FIELDS` أصلًا: المستورِد يشتقّ المفتاح بنفسه، والحالة يقرّرها
انتقال مُراجَع. ما عدا ذلك **متطابق حقلًا بحقل**.

**الحارس:** `tests/unit/content-export.test.ts` — خمسة اختبارات، أهمّها يؤكّد أن
كل كيان في `CONTENT_IMPORT_ORDER` موجود في مخرجات المصدِّر، فأيّ مجموعة تُضاف
مستقبلًا للصيغة تُسقِط الاختبار حتى يحملها التصدير. تحقّقتُ أنها تفشل فعلًا
بإرجاع الإصلاح (5 فشل / 16 نجاح).

##### ترحيل المفاتيح القديمة — Legacy key migration (2026-09-13)

**الطلب:** ترحيل المفاتيح القديمة دون نسخها كمعرّفات، وربطها بالدرس/المفهوم
المقابل أثناء الترحيل، ودون إهمالها.

**لماذا لا تُنسخ كمعرّف — سبب مقيس لا تفضيل:** مفاتيح الأسئلة القديمة
**ليست فريدة**. في الرياضيات 110 أسئلة تحت **54 مفتاحًا** فقط؛ المفتاح
`…U01-L01-Q01` وحده يخصّ ثلاثة أسئلة مختلفة في الدرس نفسه. أيّ قيد تفرُّد عليه
يرفض محتوى صحيحًا، وأيّ بحث به يُعيد الصفّ الخطأ.

وهذا ما كان يحدث فعلًا: المحوِّل كان يبني `key` من المفتاح القديم، فينتج
**38 تصادمًا** جعلت المقارنة تُظهر «فقدًا» غير حقيقي. الآن المعرّف يُشتقّ من
بصمة النصّ، والمفتاح القديم يُحفظ في `sourceRef`.

**أين استقرّ في التصميم الجديد:** عمود `sourceRef` وصفيّ على `Unit` و`Lesson`
و`Concept` و`Question` — **بلا `@@unique` عمدًا**. يجاور `origin` و`textbookRole`
الموصوفَين في المخطَّط بأنهما «provenance وصفيّ لا يُقرأ كسلطة». الربط بالدرس
والمفهوم يتحقّق بالبنية نفسها: الصفّ يحمل مرجعه القديم وهو معلَّق في موضعه
الصحيح من الشجرة.

**وأُنقذ ما كان يُهمَل:** `nameEn` و`bloomsLevel` (موجودان لكل المفاهيم الـ55،
وكانا يُحذفان صمتًا). كلاهما محتوى تحريريّ غير قابل للاشتقاق لاحقًا.

**النتيجة — الكتابان، والمقارنة الآن تشمل حقل `key` نفسه:**

```
              math            science
units          7/7  True       9/9  True
lessons       27/27 True      31/31 True
concepts      55/55 True      57/57 True
prerequisites 54/54 True      56/56 True
misconceptions 55/55 True      1/1  True
resources     55/55 True      57/57 True
questions    110/110 True    114/114 True
```

(علوم: تصوّر خاطئ واحد فقط — تحقّقت أنّها حقيقة في المصدر القديم، لا خلل.)

**الحارس:** `tests/unit/converted-packages.test.ts` (9 اختبارات) يؤكّد عدم
تصادم المفاتيح، ووجود `sourceRef` على كل عقدة، و**السماح** بتكراره صراحةً حتى
لا «يُصلحه» أحد لاحقًا بحذف أسئلة حقيقية. تحقّقت أنه يفشل بإرجاع المفتاح القديم.


**الجهد:** صغير (نصف يوم). **الأولوية: أولًا** — لأنّ كل عمل لاحق على المحتوى
يزيد ما يمكن فقده.

### 🟡 متوسط — ناقص لكن غير ضارّ

#### C2. بوابة المراجعة أضعف من المعيار المطلوب (Phase 5)

**الحقيقة المقيسة:** البوابة **موجودة وموصولة** (`POST /content/transitions`،
`GET /content/readiness`)، وتفحص فعلًا: الطبقات غير الفارغة، تتابع `orderIndex`،
المدى التربوي، حواف المتطلّبات ونطاقها، **الدورات**، والأبناء النشطون تحت أب
معطَّل. الكتاب المحوَّل يمرّ بـ`ready: true, issues: []`.

لكن معيارك يطلب فحوصًا **لا تُجرى اليوم**:

| الفحص المطلوب | الحالة | ملاحظة |
|---|---|---|
| اكتمال وحدة/درس/مفهوم | ✅ موجود | |
| صحّة `orderIndex` | ✅ موجود | |
| سلامة المتطلّبات + الدورات | ✅ موجود | |
| لا مفاتيح مكرّرة | ⚠️ **غير مفحوص هنا** | القيد الفريد في القاعدة يمنعه، لكن التقرير لا يذكره |
| ربط السؤال بالمفهوم | ❌ **مفقود** | درس بلا أسئلة يمرّ اليوم |
| صحّة `misconceptionKey` داخل الخيارات | ❌ **مفقود** من البوابة (مفحوص عند التأليف) |
| وجود الموارد المطلوبة | ❌ **مفقود** | |
| لا روابط يتيمة | 🟡 جزئي | يفحص الأب المعطَّل فقط |

**الإغلاق:** توسيع `validateStructure` بأربعة فحوص، **كلٌّ بدالّة نقيّة واختبار
طفرة**، مع تمييز صريح بين `BLOCKING` و`ADVISORY`:
- درس بلا أيّ سؤال → **blocking** (لا يمكن تقييمه).
- مفهوم بلا مورد تعلّم → **advisory** (المعالجة تضعف، لكن التعلّم ممكن).
- `misconceptionKey` لا يطابق فهرس الكتاب → **blocking**.
- مفتاح مكرّر داخل الحزمة → **blocking**.

**قرار تصميمي مهم:** التقرير يجب أن يفرّق بين «مانع» و«تحذير». بوابة تمنع النشر
على كل نقص ستُعطَّل بأول كتاب واقعي؛ وبوابة بلا موانع ليست بوابة.

**الجهد:** متوسط (1–2 يوم).

#### C3. `SUBMIT → APPROVE → PUBLISH` لم يُنفَّذ على الكتاب المحوَّل

الكتابان المحوَّلان لا يزالان `DRAFT`. البوابة تقول `ready: true`، لكن **لم
تُجرَ الرحلة**. هذا شرطك الصريح قبل بناء اللوحة.

**الإغلاق:** بعد C2، تنفيذ الرحلة الكاملة بحسابين مختلفين (`author` يقدّم،
`admin` يعتمد — ولهذا أُضيف حساب `reviewer`)، والتحقق من أنّ الكتاب يصبح مرئيًّا
للطالب **بعد** النشر وغير مرئي قبله.

**الجهد:** صغير بعد C2. **يعتمد على:** C2.

#### C4. حسابات عربية/إنجليزية/إسلامية/جغرافيا/وطنية ما زالت جذوعًا

خمس مواد بوحدة واحدة ودرس واحد. **ليست عيبًا** — هذا ما تحويه البيانات المصدر
(قيست: عربي 1و/2د/3م، إنجليزي 1/1/1، إلخ). تُسجَّل حتى لا تُفسَّر لاحقًا كفشل
تحويل.

**الإغلاق:** لا عمل هندسي. قرار محتوى: إمّا استيراد مصدر أغنى أو قبولها جذوعًا
صراحةً وعدم عرضها للطلاب.

## 2. الترتيب المقترح — Recommended order

```
C1  تكافؤ التصدير            🔴  نصف يوم   ← أولًا: يمنع الفقد الصامت
C2  توسيع بوابة المراجعة      🟡  1–2 يوم
C3  الرحلة الكاملة للنشر      🟡  نصف يوم   ← يعتمد على C2
────────────────────────────────────────────
ثمّ: لوحة المعلومات على المحتوى المنشور (شرطك)
```

**لماذا C1 قبل C2:** كلاهما يمسّ المحتوى، لكن C1 يمنع **فقدًا صامتًا** بينما C2
يمنع **نشرًا سابقًا لأوانه**. الفقد الصامت لا يُكتشف لاحقًا؛ النشر السابق لأوانه
يُكتشف فورًا ويُتراجع عنه.

**لماذا اللوحة أخيرًا:** قرارك، وهو صحيح — بناؤها على بذرة من 3 مفاهيم يثبّت
افتراضات خاطئة عن الأحجام والتقدّم والمسارات، فتُعاد كتابتها.
