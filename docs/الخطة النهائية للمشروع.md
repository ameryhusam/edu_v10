# الخطة النهائية للمشروع: Edu7 Content Engine وWorkspace واستيراد المحتوى

## 1. الغرض والنطاق

تهدف هذه الخطة إلى تحويل `Edu7 Content Engine` من محرك أولي لمعالجة ملفات PDF إلى محرك خارجي كامل لتجهيز محتوى الكتب التعليمية، ثم استيراده بأمان إلى Edu7 Backend، وتقديمه إلى Web وAndroid عند الطلب مع دعم التخزين المؤقت، والتحديث الإضافي، وتوليد الأسئلة والفلاش كارد والملخصات من المحتوى المخزن في قاعدة البيانات.

هذه الخطة مبنية على الكود الحالي في المستودع، وليس على الوثائق وحدها، وتحافظ على القواعد المعمارية الموجودة:

- `ContentImportService` هو مسار الاستيراد الرسمي.
- `ContentAuthoringService` يملك كتابة هيكل المحتوى.
- `ItemBankService` يملك كتابة الأسئلة.
- `domain/` لا يعرف Prisma أو Express أو filesystem أو مزودي الذكاء الاصطناعي.
- `application/` ينسق حالات الاستخدام من خلال ports.
- `infrastructure/` يطبق Prisma والتخزين وقراءة Workspace ومزودي AI.
- `interface/` يترجم HTTP إلى use cases ولا يحتوي منطقاً تعليمياً.
- `composition/container.ts` هو المكان الوحيد لربط implementations.
- المفاتيح canonical مشتقة من slugs، ولا تعتمد على أرقام الترتيب.
- الاستيراد يبدأ بـ `dryRun`، ولا يتجاوز دورة المراجعة والنشر.

## 2. الوضع الحالي المثبت في الكود

### 2.1 ما هو موجود

المشروع يحتوي على:

- `src/contexts/content/domain/export-profile.ts`
  - عقد `ContentPackage`.
  - الإصدار الحالي `1.1`.
  - تعريف `textbook`, `units`, `lessons`, `concepts`, `prerequisites`, `misconceptions`, `learningResources`, `questions`.
  - `answerKey.correctChoiceIds` هو الشكل canonical للإجابات.
  - المفاتيح والحالات حقول output-only ولا يكتبها المستورد كهوية.
- `src/contexts/content/application/content-import.service.ts`
  - فحص profile والإصدار.
  - فحص integrity والتكرارات والحقول المطلوبة.
  - dry-run.
  - الاستيراد عبر `ContentAuthoringService` و`ItemBankService`، وليس عبر Prisma مباشرة.
  - إعادة الاستيراد idempotent إلى حد كبير.
- `src/interface/http/content.routes.ts`
  - `POST /api/v1/content/textbooks/import`.
  - `GET /api/v1/content/textbooks/:textbookKey/export`.
  - outline، lesson materials، readiness، transitions، وإنشاء عقد المحتوى.
- `web/src/features/content/content.api.ts`
  - `importPackage`.
  - listing، outline، lesson materials، readiness، transition، export.
  - لا يكفي وحده لإثبات وجود واجهة استيراد كاملة.
- `prisma/schema.prisma`
  - `Textbook`, `Unit`, `Lesson`, `Concept`.
  - `Question`, `QuestionChoice`, `AnswerKey`.
  - `LearningResource`, `Flashcard`, `Misconception`.
  - `TextbookPage`, `ContentChunk`.
  - `LearningResource.url` و`TextbookPage.imageUrl` موجودان، لكن لا يوجد كيان موحد للأصول والـ checksum والإصدارات.
- `edu7-content-engine`
  - قراءة PDF عبر PyMuPDF.
  - اكتشاف TOC.
  - mapping بين printed page وPDF page.
  - تقطيع الكتاب إلى وحدات ودروس.
  - تحليل AI/heuristic.
  - نماذج للمفاهيم والأسئلة والمفاهيم الخاطئة والفلاش كارد.
  - JSON وExcel exporters.

### 2.2 الفجوات المؤكدة

المحرك الحالي ليس جاهزاً للربط المباشر لأن:

1. JSON exporter لا يطابق بالكامل `ContentPackage` الحالي.
2. لا يصدّر prerequisites بصيغة backend canonical.
3. لا يصدّر misconceptions إلى `misconceptions[]` بصورة كاملة.
4. لا يحول ملفات PDF والموارد إلى `learningResources[]` بروابط قابلة للاستيراد.
5. يضع `isCorrect` داخل choice، بينما Backend يتطلب `answerKey.correctChoiceIds`.
6. الفلاش كارد موجودة في نماذج Python لكنها غير موحدة بعد مع عقد الاستيراد وكتابة قاعدة البيانات.
7. صفحات الكتاب و`ContentChunk` وgrounding وpage-level citations غير مكتملة في exporter.
8. Evidence validator الحالي يتأكد من عدم فراغ evidence، لكنه لا يثبت أن النص موجود فعلياً في الصفحة المشار إليها.
9. أمر benchmark في CLI ما زال placeholder، رغم وجود `ConsensusEngine`.
10. لا يوجد Workspace manifest importer فعلي يقرأ `index.json` ويحوّل Workspace إلى package.
11. لا توجد إدارة أصول موحدة تحفظ الرابط، النوع، الحجم، checksum، الإصدار، وارتباط الأصل بالكتاب أو الوحدة أو الدرس أو المفهوم.
12. واجهة frontend لديها API client، لكن واجهة upload/preview/dry-run/apply/audit الكاملة غير مثبتة في `web/src`.
13. لا توجد دورة مكتملة ومختبرة من PDF إلى Workspace إلى Backend إلى frontend إلى learner journey وgrounded tutor.
14. لا توجد خدمة مكتملة لتوليد أسئلة إضافية من محتوى DB دون العودة إلى Workspace.

## 3. القرار المعماري النهائي

### 3.1 الفصل بين الملفات والبيانات

لا يتم تخزين الصور أو PDF داخل JSON بصيغة Base64. الملفات تحفظ كملفات فعلية داخل Workspace أو object storage، بينما JSON يحفظ metadata وروابط نسبية فقط.

```text
Workspace files / Object Storage
  PDF, PNG, JPG, TXT, MP3, MP4

JSON manifests
  relativePath, mimeType, sizeBytes, sha256, version, page range

PostgreSQL
  metadata, business relations, URLs/storage keys, pages, chunks, content records
```

### 3.2 مسارات البيانات

```text
PDF
  -> Edu7 Content Engine
  -> Workspace كامل
  -> index.json
  -> Workspace reader/validator
  -> canonical ContentPackage
  -> ContentImportService dryRun
  -> ContentImportService apply
  -> ContentAuthoringService / ItemBankService / AssetService
  -> repositories
  -> PostgreSQL + file storage
  -> asset API
  -> Web/Android fetch + cache
```

### 3.3 الكتابة الوحيدة

ممنوع أن يكتب Python مباشرة إلى Prisma أو PostgreSQL. Python يجهز Workspace وpackage فقط. Backend هو صاحب التحقق والصلاحيات والاستيراد والكتابة.

ممنوع إنشاء مسار كتابة موازٍ للـ import.

## 5. Manifest الرئيسي `index.json`

`index.json` هو نقطة دخول الاستيراد للمادة، ويحتوي على خلاصة المسارات والمحتوى والأصول والتغييرات.

يجب أن يشمل:

- `manifestVersion`.
- `type: workspace_subject`.
- term، grade، subject، edition.
- metadata الكتاب.
- نسخة Edu7 Content Engine.
- counts للمحتوى والأصول.
- مسارات الوحدات والدروس.
- checksum لكل asset أو manifest.
- رابط/مسار `edu7-content-package.json`.
- `contentVersion` و`updatedAt`.
- hash canonical للمحتوى.

مثال مختصر:

```json
{
  "manifestVersion": "1.0",
  "type": "workspace_subject",
  "workspaceId": "T01-G07-MATH",
  "term": "T01",
  "grade": "G07",
  "subject": "MATH",
  "edition": "2026",
  "title": "كتاب الرياضيات للصف السابع",
  "source": {
    "engine": "edu7-content-engine",
    "engineVersion": "1.2.0",
    "sourcePdf": {
      "relativePath": "textbook/textbook.pdf",
      "mimeType": "application/pdf",
      "sizeBytes": 123456789,
      "sha256": "..."
    }
  },
  "counts": {
    "units": 2,
    "lessons": 4,
    "concepts": 18,
    "questions": 72,
    "flashcards": 36,
    "resources": 14,
    "assets": 28
  },
  "units": [
    {
      "unitNumber": 1,
      "slug": "algebra",
      "relativePath": "unit_01_algebra",
      "manifest": "unit_01_algebra/unit_01.json",
      "pdf": "unit_01_algebra/U_01_algebra.pdf",
      "lessons": [
        {
          "lessonNumber": 1,
          "slug": "linear-equations",
          "relativePath": "unit_01_algebra/lessons/lesson_01_linear_equations",
          "manifest": "unit_01_algebra/lessons/lesson_01_linear_equations/lesson_01.json",
          "pdf": "unit_01_algebra/lessons/lesson_01_linear_equations/L_01_linear_equations.pdf"
        }
      ]
    }
  ],
  "package": {
    "relativePath": "edu7-content-package.json",
    "profile": "edu7.textbook-content",
    "profileVersion": "1.1"
  },
  "contentVersion": 3,
  "updatedAt": "2026-09-20T12:00:00Z",
  "contentHash": "..."
}
```

### تحديث `index.json`

عند أي تغيير:

```text
question/asset/resource change
  -> lesson JSON update
  -> unit JSON update if needed
  -> canonical package rebuild
  -> index.json rebuild
  -> new contentHash
```

لا تعتمد المقارنة على `updatedAt` فقط. المقارنة الأساسية هي checksum وcanonical content hash.

اختفاء عنصر من Workspace لا يعني حذفه من DB. يجب أن يسجل كـ `missing_from_source` أو `conflict`، ولا يتم الحذف إلا بأمر retire/archive صريح.

## 7. تعديلات قاعدة البيانات

### 7.1 إضافة `ContentAsset`

النماذج الحالية `LearningResource.url` و`TextbookPage.imageUrl` لا تكفي لإدارة asset lifecycle. أضف في `prisma/schema.prisma`:

- `ContentAssetType`.
- `ContentAsset`.
- علاقات اختيارية إلى `Textbook`, `Unit`, `Lesson`, `Concept`.
- `assetId` اختياري في `LearningResource`.

الحقول المطلوبة:

```text
id
key
assetType
originalName
relativePath
storageKey
publicUrl أو access route
mimeType
sizeBytes
sha256
version
isActive
textbookId
unitId
lessonId
conceptId
pageStart
pageEnd
createdAt
updatedAt
```

أنواع الأصول المقترحة:

```text
TEXTBOOK_PDF
UNIT_PDF
LESSON_PDF
PAGE_IMAGE
PAGE_TEXT
RESOURCE_FILE
IMAGE_SUMMARY
AUDIO
VIDEO
```

لا تحوّل `LearningResource` إلى مخزن ملفات. `LearningResource` يمثل المادة التعليمية، و`ContentAsset` يمثل الأصل الفيزيائي.

### 7.2 لا تخزن PDF داخل PostgreSQL

يحفظ PostgreSQL:

```text
metadata + storageKey + checksum + relations
```

ويحفظ storage:

```text
PDF/image/audio/video binary
```

التنفيذ الأول يمكن أن يستخدم local mounted storage، لكن يجب تعريف `ContentStorage` port بحيث يمكن تبديله لاحقاً بـ S3/CDN/object storage من `composition/container.ts`.

### 7.3 الجداول الحالية التي يجب استخدامها

- `TextbookPage`: نص الصفحة ورابط صورة الصفحة.
- `ContentChunk`: مقاطع grounding مرتبطة بصفحة وlesson/concept.
- `LearningResource`: مادة القراءة/الفيديو/المورد المعروضة.
- `Flashcard`: محتوى الفلاش كارد بدون scheduling state.
- `Misconception`: مفهوم الخطأ التشخيصي.
- `Question` و`AnswerKey`: بنك الأسئلة canonical.

لا تضف جداول بديلة للوحدات أو الدروس أو الأسئلة.


يجب أن تُحل العلاقات قبل كتابة العناصر التي تعتمد عليها. prerequisites قد تكون cross-textbook، أما questions فترتبط بمفاهيم داخل نفس الكتاب.

### 9.4 إصلاح answer choices

لا يخرج المحرك:

```json
{
  "id": "a",
  "text": "...",
  "isCorrect": true
}
```

بل يخرج:

```json
{
  "choices": [
    { "id": "a", "text": "...", "orderIndex": 1 },
    { "id": "b", "text": "...", "orderIndex": 2 }
  ],
  "answerKey": {
    "correctChoiceIds": ["a"],
    "acceptedTexts": [],
    "numericMin": null,
    "numericMax": null,
    "caseSensitive": false,
    "allowPartialCredit": false
  }
}
```

`isCorrect` يمكن أن تستخدم داخلياً في Python أثناء التحليل، لكنها تُزال من canonical export ويُحوّل معناها إلى `answerKey.correctChoiceIds`.

### 9.5 prerequisites

المحرك يجب أن ينتج لكل علاقة:

```json
{
  "conceptKey": "...",
  "prerequisiteKey": "...",
  "strength": 1.0,
  "requiredMastery": 0.7
}
```

لكن Python لا يخترع canonical keys. إذا كانت العلاقة داخل نفس package، يجب أن يخرجها بصورة slug paths وسيقوم `package_builder` أو Backend converter بحلها إلى keys. إذا كانت خارج الكتاب، يجب أن يكون المفتاح الخارجي مصرحاً به في source data ويُسجل كـ external prerequisite.

لا يتم إسقاط prerequisites، لأنها ضرورية لمسار التعلم و`next-step` وroot-gap analysis.

### 9.6 misconceptions

كل misconception تخرج إلى `misconceptions[]` المستقلة:

```json
{
  "slug": "sign-error",
  "unitSlug": "algebra",
  "lessonSlug": "linear-equations",
  "conceptSlug": "solving-linear-equations",
  "name": "خطأ الإشارة",
  "description": "...",
  "correction": "..."
}
```

ولا تظل محصورة داخل concept أو choice. خيارات السؤال تشير إليها بـ `misconceptionKey` أو local reference يحله converter.

### 9.7 resources

كل PDF درس أو وحدة، وكل reading/remedial/image/video، يتحول إلى resource/asset mapping:

```text
lesson PDF -> LESSON scoped LearningResource + LESSON_PDF ContentAsset
unit PDF -> UNIT asset
reading PDF -> LESSON/CONCEPT resource + RESOURCE_FILE asset
summary image -> CONCEPT/LESSON resource + IMAGE_SUMMARY asset
page image -> TextbookPage.imageUrl + PAGE_IMAGE asset
```

بهذا تصبح endpoints التالية قادرة على إعادة المواد الفعلية:

```text
GET /api/v1/content/lessons/:lessonKey/materials
GET /api/v1/learning/lesson
```

### 9.8 flashcards

المحرك يخرج flashcards في مجموعة مستقلة أو ملف lesson-level، ثم يحولها package builder إلى العقد canonical. Backend يكتبها عبر service/repository مالك `Flashcard`، ولا يضيف scheduling state أو learner state.

### 9.9 pages/chunks/grounding

المحرك يجب أن يصدر:

- `textbookPages[]` أو page records.
- `contentChunks[]`.
- page number printed وPDF page.
- source excerpt/evidence.
- relation إلى unit/lesson/concept.
- image asset link.

إذا لم يكن profile الحالي يحتوي هذه المجموعات، يتم توسيعه minor-compatible أو تنفيذ adapter داخلي package-to-grounding، مع tests. لا يتم تجاهلها لأن grounded tutor يعتمد على `TextbookPage` و`ContentChunk` وليس فقط على أسماء المفاهيم والأسئلة.

### 9.10 Evidence validator

تعديل:


## 13. تحديث المحتوى وعدم حذف البيانات

### 13.1 الهوية

- الوحدة: `textbookKey + unitSlug`.
- الدرس: `unitKey + lessonSlug`.
- المفهوم: `lessonKey + conceptSlug`.
- السؤال: هوية السؤال الحالية هي النص داخل الدرس حسب العقد؛ لا تعدل stem القديم بصمت.
- المورد: scope + qualified target path + slug.
- الأصل: qualified target + relativePath/slug + sha256/version.

### 13.2 النتائج

```text
same fingerprint -> unchanged
new fingerprint -> create
same identity + changed content -> conflict أو version/update صريح
missing from new source -> preserve
explicit retire -> archive/retire
```

### 13.3 الأسئلة

- لا تستخدم `isCorrect` في package.
- لا تعيد إنشاء السؤال نفسه.
- نفس lesson + نفس canonical text + نفس answerKey = unchanged.
- نفس stem وإجابة مختلفة = conflict، ولا تستبدل القديم بصمت.
- السؤال الجديد من AI يدخل `DRAFT`.
- لا تحذف question بسبب اختفائه من `questions.json`.
- لا تعدل سؤالاً يحمل evidence أو learner responses إلا عبر workflow صريح.

### 13.4 المفاهيم

إذا تطابق path canonical، لا تنشئ مفهوم duplicate بسبب تغير orderIndex. التغيير النصي يحتاج authoring update صريحاً ومراعاة learner evidence.

### 13.5 resources/assets

نفس slug ونفس checksum = unchanged.
نفس slug وchecksum مختلف = version/conflict.
اختفاء asset لا يحذفه تلقائياً.

يفضل إضافة `ContentImportBatch` و`ContentImportItem` لاحقاً لتسجيل:

- source manifest hash.
- actor/engine.
- created/unchanged/conflict/rejected.
- asset versions.
- problems.

ولا تنشئ هذه الجداول قبل تثبيت domain contract واستخدام فعلي واضح لها.
