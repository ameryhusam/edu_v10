# تحليل الفجوات وخطة الجاهزية للإنتاج — Edu7

تاريخ المراجعة: 2026-09-15

## المقارنة المختصرة مع أنظمة تعليمية متقدمة

- **Moodle / Canvas:** نقاط القوة الإنتاجية فيها هي فصل المحتوى عن الإسناد، سجلات تدقيق، صلاحيات مؤسسية، واستيراد/تصدير منظّم. Edu7 أصبح قريبًا في الفصل بين الكتاب، التبنّي، الواجبات، والمهام الاستشارية، لكن يحتاج مراقبة تشغيلية ونسخ احتياطي قبل الإنتاج.
- **Khan Academy / Duolingo:** القوة في mastery/adaptive loops والعودة من آخر نقطة. Edu7 يملك نموذج mastery ومسارًا تكيفيًا، وأضيفت حماية نقص أسئلة CAT، لكن يحتاج تغذية أوسع للأسئلة الوزارية ومعايرة IRT بعد بيانات حقيقية.
- **Google Classroom:** القوة في بساطة التكليف والمتابعة. Edu7 أضاف إنشاء/نشر/إسناد/نتائج، لكن UX المعلم يحتاج دفعة لاحقة للتجميع حسب الشعبة الافتراضية والمواد.
- **Moodle Mobile / تطبيقات المدارس:** القوة في offline shell، push notifications، وAndroid packaging. أضيف أساس PWA الآن؛ التحويل إلى Android يحتاج اختيار TWA أو Capacitor ثم اختبارات WebView/أجهزة.

## ما تم إصلاحه في هذه الدفعة

1. **مصدر المناهج اليمنية:** أضيف ملف JSON منظم حسب الصف/المادة/الفصل (91 مصدر PDF مبدئيًا للصفوف G01–G09) في `prisma/seed/data/external/yemen-moe-textbook-sources.json` مستند إلى قناة تيليجرام المطلوبة وموقع الوزارة كمسار بديل قابل لإعادة الاستخراج.
2. **تغذية قاعدة البيانات:** أضيف seed loader في `prisma/seed/source-catalog.ts` يقرأ الفهرس ويُنشئ/يحدّث كتبًا Draft حسب الإحداثيات الرسمية، ويربط كل PDF كمورد `TEXTBOOK_PAGE` على مستوى الكتاب، دون نشره تلقائيًا للطلاب.
3. **منع قناة خلفية:** تم إبقاء PDF الخام كمورد ومصدر مراجعة فقط؛ تحويله إلى وحدات/دروس/مفاهيم/أسئلة يبقى عبر حزمة المحتوى وبنك الأسئلة حتى لا تدخل بيانات غير مدققة إلى التعلم التكيفي.
4. **توافق مسار الموارد:** الفهرس الجديد يغذي نفس نموذج `LearningResource` ونوع `TEXTBOOK_PAGE` الذي تستخدمه واجهات إضافة موارد الدرس/الكتاب وبنك الأسئلة، بلا مسار كتابة خلفي جديد.
5. **جاهزية Android/PWA:** أضيف manifest، service worker، offline page، وأيقونة SVG، مع عدم تخزين أو مزامنة إجابات الاختبارات الحساسة في الخدمة العاملة.
6. **توثيق الفجوات الإنتاجية:** سُجّلت الحدود التي لم يُسمح بتجاوزها آليًا: لا OCR غير مدقق في seed، ولا تحويل “وزاري” إلى نوع سؤال، ولا تخزين لمحاولات الامتحان في service worker.

## مسار استخراج المحتوى اليمني المعتمد

1. المصدر الاجتماعي المطلوب: `https://t.me/Books_Yemen_new`.
2. المصدر القابل للأتمتة عند تعذر أرشيف تيليجرام: `http://e-learning-moe.edu.ye/book.php` وصفحات الصفوف التابعة.
3. أمر التحديث عند توفر وصول شبكي مباشر لصفحات الوزارة (يفشل دون كتابة ملف إذا حجبت الشبكة المصدر):

```bash
node scripts/extract-yemen-moe-catalog.mjs --out prisma/seed/data/external/yemen-moe-textbook-sources.json
```

4. بعد مراجعة JSON، تشغيل seed يضيف مصادر PDF إلى قاعدة البيانات كموارد كتابية. تم التحقق محليًا بإدخال 91 مصدر PDF عبر 89 إحداثية كتابية:

```bash
npm run db:seed
```

5. استخراج النص التفصيلي من PDF يجب أن ينتج Content Package مراجعة قبل النشر: كتاب → وحدات → دروس → مفاهيم → موارد → أسئلة.

## فجوات متبقية قبل الإنتاج

- **استكمال الثانوية G10–G12:** السكربت يعرف صفحات الثانوية، لكن الفهرس المراجع الملتزم حاليًا يغطي G01–G09 فقط حتى لا ندخل mapping ثانوي غير مدقق.
- **استخراج PDF/OCR كامل:** يلزم عامل معالجة منفصل لاستخراج النص والجداول والصور من PDF، ثم مراجعة بشرية قبل النشر. لا يُنصح بجعل seed يحمل OCR غير مدقق.
- **تخزين ملفات الإنتاج:** يجب نقل PDFs والصور إلى object storage/CDN أو proxy موثوق بدل الاعتماد الدائم على روابط خارجية.
- **الأسئلة الوزارية:** نحتاج قناة/أرشيف قابل للتنزيل لنماذج الامتحانات الوزارية، ثم parser منفصل يحفظ `QuestionOrigin=MINISTERIAL` و`sourceRef` سنة/دور/صف/فصل، ولا يجعل “وزاري” نوع سؤال.
- **الملاحظة والتشغيل:** logging مركزي، metrics، tracing، alerts، rate limits، backups، وسياسة retention لسجلات المحاولات.
- **الأمان:** CSP نهائي، مراجعة CORS/cookies، تشفير أسرار الإنتاج، مراجعة صلاحيات multi-school للمعلمين، واختبار اختراق أساسي.
- **Android:** بعد PWA، القرار العملي: TWA إذا بقي التطبيق ويب بالكامل، أو Capacitor إذا احتجنا إشعارات/ملفات محلية/كاميرا. في الحالتين يجب اعتماد deep links، icons raster، splash، واختبار offline/refresh-cookie داخل WebView.

## مقترحات تحسين إضافية

- لوحة جودة للمحتوى تعرض: كتب بلا وحدات، دروس بلا قراءة، مفاهيم بلا أسئلة، أسئلة بلا روابط، CAT pools starved، وأسئلة بانتظار تصحيح يدوي.
- خط إنتاج أسئلة وزارية: رفع PDF/صور → OCR → معاينة → ربط درس/مفهوم → اعتماد → نشر.
- توصيات للمعلم مبنية على نتائج الاختبار: مجموعات علاجية، أسئلة صعبة، ومفاهيم ضعيفة.
- تنزيل موارد الكتاب للقراءة دون اتصال مع حدود واضحة: الموارد فقط، لا محاولة اختبار كاملة إلا بعد تصميم مزامنة آمنة.
- واجهة Admin لمراجعة فهرس مصادر الوزارة: فلترة حسب الصف/المادة/الفصل، فتح PDF، وتحويله إلى حزمة محتوى.
